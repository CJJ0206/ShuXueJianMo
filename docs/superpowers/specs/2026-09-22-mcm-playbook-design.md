# 研究生数学建模竞赛 参赛作战包 —— 设计文档

日期：2026-09-22　状态：待评审
适用范围：中国研究生数学建模竞赛（3 人队，AI 主力执行）
本文档定义**交付物**，不定义任何具体赛题的解法。2025 年 A–F 六题只作为流程夹具。

---

## 1. 目标与非目标

### 目标
产出一套明天开赛即可上场的作战包，含四件东西：

1. **《执行规范（我侧）》** —— 开赛前 36 小时内，用户 + AI 如何产出"全题初版方案"。
2. **《验收规范（全队）》** —— 用可机器判定的 V0–V3 四级验收，判定初版能否交接、终稿能否提交。
3. **prompt 卡片库**（30 张）—— 每张卡对应流程里一个动作，含变量占位、必落文件、人工判定项。
4. **工程脚手架** —— 目录模板 + 单一事实源文件 + 自动检查脚本。

### 非目标
- **不求解任何一道题。**今晚与明天都不产出题目答案。
- 不做具体模型的选型（模型选择是明天按当天赛题现场决定的事）。
- 不搭建 Qoder Skill / 不做自动化编排。全流程靠人复制粘贴 prompt 驱动——依赖越少，赛场故障模式越少。

│   ├── 0-选题.md  1-题面解析.md  2-建模.md

└── scaffold/

### 3.1 六份事实源文件（全流程的血管）

固定 schema：**一行一条目、ID 前缀写死、字段用 `|` 分隔、禁止用散文段落承载关键信息**。理由：接手方的 AI 会直接读这些文件；散文里的约束会被漏读，字段不会。

| 文件 | ID | 字段 | 所有权 |
|---|---|---|---|
| `SPEC.md` | `C##` | 题面原文引用 \| 解读 \| 硬/软 \| 单位 \| 建议验收断言 \| 所属小问 | **只读**（仅 R1/R3 全员会可改） |
| `assumptions.md` | `A##` | 假设内容 \| 理由 \| 影响面 \| 验证方式 \| 若为假结论如何变 | 仅全员会可改 |
| `numbers.md` | `N##` | 值 \| 单位 \| 来源脚本路径 \| 出现位置 \| 复算方式 | 任何班可追加，不可改值 |
| `decisions.md` | `D##` | 决策 \| 备选 \| 选择理由 \| 放弃代价 \| 时间 | 追加式 |
| `issues.md` | `I##` | 定位(小问/`C##`) \| 类别 \| 影响面 \| 当前假设 \| 建议验证 \| 优先级 \| **复现命令** \| owner | 追加式，owner 唯一 |
| `handoff.md` | — | 当前状态 \| **已排除路线及原因** \| 最可疑三处 \| 下一步三条 | 交接班写，接接班追加 |

**硬规则：论文、代码、图表里只引用编号，不允许把数值或假设抄第二遍。**

## 4. 阶段与时间盒

默认为 4 天 ≈ 88h 有效工时。若明早确认赛制更短，按比例压缩 P2 与 P4，**选题、交接、V3 三个时间盒不压缩**。

| 阶段 | 时间盒 | 主力 | 出口 |
|---|---|---|---|
| 今晚 赛前准备 | — | AI | 作战包过 §10 的自检 |
| P0 选题 | ≤ 3h | 人判，AI 出表 | 定题 + `D01` |
| P1 题面解析 | ≤ 5h（与 P0 重叠 1h） | AI 抽取，人核对 | **Gate R1**，`SPEC.md` 冻结为只读 |
| P2 初版全案冲刺 | D0.5 → D1.5，≈22h | 用户 + AI | **V0 交接验收** |
| P3 交接会 | D1.5，2h | 三班会同 | 交接通过，进入两班制后段 |
| P4 支援期 | D1.5 → D4 | 另两班 + AI | **R2**（逐小问）、**R3**（提交前） |

**论文不独立成段**：论文骨架从 P2.1 就开始写，不等结果。空章节过不了 V1，所以这条是硬约束而非建议。

### 4.1 预先写死的砍单线

| 触发 | 动作 |
|---|---|
| 任一小问连续 3h 零进展 | 强制换模型或降复杂度，登记 `D##` 记理由 |

| 剩余 < 12h | 停一切新求解，全力成文（残缺论文有分，完整代码没有） |
| 剩余 < 4h | 只做 V3 修补与提交演练 |
| 提交前 90min | **内容冻结硬闸**，只允许 V3-5 格式类修改 |

## 5. 三轮审查会（时间点）与验收判据（内容）

命名关系：`R1/R2/R3` 是审查会；`V0–V3` 是会上用的判据。R1 ≈ V1 + 题面勾验；R2 = V2（逐小问触发，非最后统一）；R3 = V3；V0 仅在 P3 交接那一刻用一次。

### R1 题面审查（P1 末，全员到场 60–90min）
AI 产出：约束清单 / 歧义清单 / 假设表 / 小问依赖图。
三人分工：**甲**查"漏了哪条约束"、**乙**查"题意读大了还是读小了"、**丙**查"哪个小问其实做不了"。
不通过的动作是**回炉重读题面**，不是"改一改"。理由：此时返工最便宜，之后返工代价最高。

### R2 证据审查（每小问出结果即触发，15–20min）
**人不看代码，只看证据包。**任一判据红 → 该结论在论文里必须降级标注"未验证"，**不允许"先写着回头补"**。

### R3 一致性与可提交性审查（提交前 ≥3h 启动，120min）
先机器扫一致性，再 AI 切评委视角出"最可能被质疑的 12 问"，逐条给出处置。90min 硬闸后只允许格式修补。

## 6. 验收规范

### V0 交接验收（D1.5，60min，判定权归接手人，交接班闭嘴）

| 编号 | 判据 | 方式 | 不通过动作 |
|---|---|---|---|
| V0-1 冷启动 | 开**全新 AI 会话**，仅喂四样输入（题面原文、`SPEC.md`、`issues.md`、目录树），要求产出"每问要算什么 / 现在到哪 / 下一步三条"。与交接班所写 `handoff.md` 命中率 **≥80%** | `coldstart.py` 打包 + 人判命中 | 回炉补文档。**命中率不足不是新会话笨，是移交包欠规格** |
| V0-2 复述 | 接手人只读移交包 20min，复述任一小问的"目标/模型/当前结果/最可疑三处"，命中该问硬约束 ≥80% | 人判，对照 `SPEC.md` 逐条勾 | 补文档，不许"他们自己看代码" |
| V0-3 一键复现 | 接手人**自行**执行 `run_all.py`：结果与移交值一致、无报错、种子固定 | 脚本 | 交接失败，交接班当晚补 |
| V0-4 在册抽验 | 从 `issues.md` 抽 3 条跑其复现命令，确认描述真实且准确 | 脚本 + 人 | 虚假/夸大登记记为漏报 |
| V0-5 反向发现 | 接手人 30min 自由审查，尝试找出 ≥1 条**未登记**问题 | 人 | 找到即当场补登记并复盘"为何未被发现" |

核心原则：**登记过的瑕疵是资产，未登记的瑕疵是事故。**

### V1 结构验收（`check_structure.py`，≤10min，每小问完成即跑）
非 0 退出即禁止进入下一环节。检查项：目录与命名合规 · 每小问交付物齐（`spec.md`/`src`/`results`/`verify.py`）· 六份事实源文件存在且非空 · **占位符扫描**（`TODO`/`待补`/`XXX`/空章节，0 容忍）· `numbers.md` 每条有来源脚本路径 · 图表公式编号连续且正文有引用。

### V2 证据验收（逐小问，六项全绿才算该问成立）

| 判据 | 阈值 |
|---|---|
| V2-1 独立复算 | **双路一致只是必要条件，不是充分条件**（今晚实测：两个都错的答案相差 1.00 bin 却判 PASS）。通过须四条同时成立：① `verify.py` 走不同算法路径（静态检查：不得 import 求解模块）② 结果落在**求解前独立写下**的粗估区间内（卡 2-2）③ 合成锚点取回已知值 ④ 两路不得共享被检验的那个假设。**容差按算法性质定义**：闭式确定性 ≤1e-6；离散谱/迭代/启发式按该算法自身的分辨率或收敛阈定义（例：FFT 主频的比较容差是"≤1 个频率分辨单元"，写 1e-6 是错的），且须在 `verify.py` 头部写明该分辨率数值。随机算法须 5 个 seed |
| V2-2 量纲与取值域 | 每个 `N##` 有单位字段且与 `SPEC.md` 单位约定一致；换算只经单一 `units.py` |
| V2-3 退化特例 | ≥1 个可解析退化情形（N=1 / 无约束 / 参数取退化值）退回已知解析值或题面示例值，误差 ≤1% |
| **V2-4 约束逐条勾验** | `SPEC.md` 中该问**每条硬约束对应一个可执行断言且全绿，覆盖率必须 100%**。这是防止 AI 悄悄放宽约束刷出漂亮结果的唯一屏障 |
| V2-5 边界极端输入 | 空/最大/并列/不可行情形不崩、不输出无意义最优 |
| V2-6 可复现 | 固定 seed、`env.lock` 记版本、同输入两次运行逐位一致 |

### V3 一致性与可提交性验收（全队 120min）

| 判据 | 方式 | 阈值 |
|---|---|---|
| V3-1 数字四处一致 | `check_numbers.py` 扫正文，所有数值须为 `N##` 引用 | 同值不同源 0 项；同源不同值 0 项 |
| V3-2 假设闭环 | 每条 `A##` 正文至少引用 1 次且带影响说明；正文模型设定均可溯源到 `A##` | 无来源设定 0 容忍 |
| V3-3 符号与文献 | 符号表覆盖全部数学符号；参考文献可解析 | 未登记符号 0 |
| V3-4 图表 | 单位/编号/正文引用齐，矢量或 ≥300dpi，灰度可辨 | 0 |
| V3-5 格式合规 | 页数、摘要页、编号页、附录打包清单、文件命名、PDF 体积 | 逐项勾官方模板 |
| V3-6 评委挑刺 | AI 出 12 问，每条要么正文有答要么进"模型评价与推广" | 未处置 ≤1 |
| V3-7 附件完备 | `issues.md` 全部 P0 关闭；结果文件按题面要求命名/格式存在 | P0 未关 0 |

### 5 个 KPI（验收规范必须可打分）

| KPI | 定义 | 目标 |
|---|---|---|
| 瑕疵在册率 | 已登记 ÷（已登记 + 验收中新发现） | ≥90% |
| 约束覆盖率 | 有可执行断言的硬约束 ÷ 全部硬约束 | 100% |
| 数字台账引用率 | 正文中带 `N##` 的数值 ÷ 全部数值 | ≥95% |
| 一键复现成功率 | 接手人自行跑通 ÷ 尝试 | 100% |
| 冷启动通过率 | 新会话命中 ≥80% 次数 ÷ 尝试 | 100%（交接前后各跑一次） |

### 角色矩阵
V0 接手人判 · V1 脚本（谁交谁跑）· V2 作者跑 + 第二人判 · V3 全队，丙主持 · 交叉复算的"验证方"由**非求解班组**担任。

## 7. 多 AI 并行的防腐机制

三台 AI 同时作业的技术收益是互不信任的三次验证，风险是事实分叉。四条机制：

1. **`SPEC.md` / `assumptions.md` 只读。**任何 AI 不得改题面约束的解读；要改只能提 `I##`，由 R1/R3 全员会裁决。
2. **按 `I##` 分区作业。**一个条目只有一个 owner；不分区必然冲突。
3. **交叉复算。**A 班 AI 求解的结果，必须由另一班 AI 写的 `verify.py` 独立复算。同一条 AI 路径自证为绿不算绿。
4. **`handoff.md` 必含"已排除路线及原因"。**三 AI 并行最大浪费是后一班把前一班的坑重踩一遍，因为它看不见失败历史。每条格式：`路线 | 试到什么程度 | 为何放弃 | 证据文件路径 | 什么条件下值得重试`。

**用户的 P4 角色固定为编排者 + 仲裁者**，只做三件事：分派 `I##`、跑 V1/V2 脚本、在两班 AI 结论冲突时按编号证据裁决。**不亲自下场写代码**——一写就把仲裁位让出去了。

## 8. 执行规范（我侧）

### 8.1 P0 选题（≤3h，内部严格排序）

| 步 | 时间 | 动作 | 为什么在这个位置 |
|---|---|---|---|
| P0.a | 0–5min | 拿到全部题面（PDF/DOCX） | — |
| P0.b | 5–25min | **硬门槛过滤 + 拥挤度推断**（只读题面，不需附件） | 拥挤度评估不依赖下载，把它排前面可避免把最贵的等待串行化 |
| P0.c | **并行**，5–60min | 另一名队员下载全部附件并跑 `附件数据体检卡` | 体检结论反过来修正拥挤度的 S3 信号 |
| P0.d | 25–85min | 三维评估（可达性/风险/拥挤度）→ 剩 2 候选 | — |
| P0.e | 85–145min | 两候选各跑可行性探针，每候选 30min，各出 1 页 memo | — |
| P0.f | 145–175min | 裁决，写 `D01`（含放弃另外各题的理由） | 明天复盘要用 |

**硬门槛（任一命中直接出局，不进评分）**：需要编译原理/计算机体系结构背景；需要信息论或通信 PHY 层推导；需要专有硬件或无法获得的数据。
理由：这类题也是 AI 最容易产出"看似完整、实则错误"结果的题型。

**三维评估**

- **① 二等奖可达性**：完成度可交付性（四问都能交东西吗）· 评分弹性（有无客观数字被认出来，纯主观题区分度差）· 创新展示位（有无一处让评委记住）· AI 杠杆率（调参/跑基线/画图杠杆高，物理建模正确性杠杆低）。
- **② 风险**：数据可得性（一票否决）· 算力与时间爆雷 · 结果不可自证（无客观判据则只能靠论证，写作成本最贵）· 评委主观性 · 同质化（同一公开数据集 + 同一结构，区分度变成运气）。
- **③ 拥挤度**（见 §8.2）。

### 8.2 拥挤度五信号（全部由题面观测，每张卡必须附"我凭什么这么判"并引用题面原文）
| 信号 | 量化方式 | 方向 |
|---|---|---|
| S1 开放性（**最强预测器**） | 题面是否给定评价指标/阈值/结果文件格式；"请建立体系评价 X"式表述 → 弱队也敢交卷 | 越开放越挤 |
| S2 技能栈宽度 | 所需技能是通用（回归/规划/评价）还是领域专有；代理指标：非通用专业术语密度（术语数/千字） | 越通用越挤 |
| S3 数据与格式摩擦 | 附件规模、格式常规度（xlsx/csv 零摩擦；DWG、雷达基数据、netCDF、二进制高摩擦）、是否需网盘/外网/GPU | 摩擦越高越冷 |
| S4 题材热度 | 命中年份导向关键词（低空经济、双碳、AI/大模型、智慧农业、交通、文旅美学…） | 越热越挤 |
| S5 算力与工作量天花板 | 数据量级、是否需训练、4 天内单机是否可完成 | 越重越冷（双刃，见下） |

加权聚合。**注意 S3、S5 与拥挤度反号**（摩擦越高、工作量越重 → 越冷），必须取反向项 `(6−S3)`、`(6−S5)` 再加权，否则排序会整体反转：

```
crowd = ( 1.5×S1 + 1.2×S2 + 1.2×(6−S3) + 1.0×S4 + 0.8×(6−S5) ) / 5.7     ∈ [1,5]
```

权值和 5.7，分子落在 [5.7, 28.5]，故 crowd 天然落在 [1,5]，保留一位小数。
S2 的刻度写死以免各队自行解释：`非通用专业术语数 ÷ (题面字符数/1000)`，≤1→5 分、1–3→4、3–6→3、6–10→2、>10→1。
映射为二等奖门槛线：`crowd ≥4` → 选做占比 >30%，需该题前 8%；`3–4` → 15–30%，前 12%；`2–3` → 8–15%，前 18%；`≤2` → <8%，前 25%。
禁止先取整 crowd 再倒推档位。附件体检完成后 S3 允许回填重算一次（得 v2 表），但 **v1 表必须保留**，明天复盘要看推断怎么变的。

**两条使用规则**
- 只用于排序与淘汰，不用于绝对概率。题面推断误差量级 ±10 个百分点，够判"A 比 B 挤"，不够判"我们能进前 8%"。
- **机会题例外**：`S5 ≥ 4` 且 `可达性 ≥ 3.5` 时，覆盖拥挤度扣分直接进候选。这类题冷是因为做不出来、不是没人想做，只要本队 AI 主力真跑得动，性价比最高。

### 8.3 决策规则（写死，防现场摇摆）

> 选"本队能力剖面与该题评分剖面错位最大"的题，而不是"最好做"的题。
> 具体：在 `可达性 ≥3.5` 且 `风险 ≤3` 的题里选 **拥挤度最低**者；三题并列时选**评分弹性最高**者（宁要能算出数字的题，不要靠审美判断的题）。
