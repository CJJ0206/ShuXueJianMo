# 组 4 · 论文（卡 4-1 … 4-6）

判据来源：`docs/superpowers/specs/2026-09-22-mcm-playbook-design.md` §3.1、§4、§5（R3）、§6（V1/V3）、§8.4。
格式契约：`数模作战包/scaffold/scripts/schema.py`；目录结构：`数模作战包/scaffold/scripts/bootstrap.py`。

**本机无 LaTeX、无 Word、无 MATLAB、无 LibreOffice**（见 `数模作战包/SETUP.md` 第 2 节）。
论文路线因此固定为：**分节 Markdown 成文 → 机器扫描判绿 → 粘进 `paper/main.docx` 由 WPS 排版 → 导出 PDF 提交**。
由此派生三条本组通用规则，每张卡都按它执行：

1. **可扫描的正文只有 `paper/sections/*.md`。** `check_numbers.py` 只读这个目录，Word 里的数字机器看不见，
   所以一切数值与编号的处置必须在 Markdown 阶段做完，导 PDF 之前不再改内容。
2. **没有自动交叉引用。** 图号/表号/式号全靠 `paper/编号表.md` 人工维护，任何增删都要回改编号表并全文重扫
   （spec §13 的教训："我改过了"不是证据，全文重扫才是）。
3. **只引用编号，不抄第二遍。** 正文里的数值写 `值 [N##]`、假设只写 `A##`、约束只写 `C##`（spec §3.1 硬规则）。

> 本组 6 张卡今晚未进压测范围（spec §10 只压组 0 与组 1），首次使用按"未验证工具"对待：
> 先在低风险小问那一节用一次，确认输出形态，再全量用。


### 卡 4-2  摘要三段式
- **触发时机**：每小问的自证包（卡 3-2）转绿后写一次该问的摘要句；全部小问齐了合成整段。位置在 P2.3 与 R3 之间，但**提交前 90 分钟由卡 5-6 复核最后一遍**，此后不再改。摘要页文件 `00-摘要.md` 由卡 4-1 建，不得等结果才建。
- **输入**：`{SPEC.md 全文}`、`{assumptions.md 全文}`、`{numbers.md 全文}`、`{每问方法与关键假设一句话}`、`{每问代表结果的 N##}`
- **prompt**：
```text
写论文摘要（paper/sections/00-摘要.md，评委真正读的第一页，也是唯一一页）。
全文只允许三段，顺序不得调换、不得增删段落，每段第一句先给出段意在回答什么。

第 1 段 问题是什么：1–3 句，写清研究对象与每一小问要算出的量（带单位），
  每句末标注它回答的 C##。禁止复述题面的背景故事与行业意义。
第 2 段 怎么建的：逐问一句，形如
  "针对问题 1（C05），在 A02、A03 下建立 XXX 模型，用 YYY 求解"。
  方法名必须是具体算法（整数规划分支定界 / VMD+小波阈值去噪 / 加权最小二乘 /
  Dijkstra 变体 这类），不写"建立了数学模型""采用智能算法求解"。
  假设只写 A## 编号，不抄内容。
第 3 段 关键数字：每问至少一个代表结果，格式 `值 [N##]（单位）`，
  再各给一条检验证据，形如"独立复算相对误差 2.1e-7 [N12]（无量纲）"、
  "退化到 N=1 时与解析值一致，误差 0 [N09]（%）"。
  台账里没有的数字，一个都不许出现在摘要里。
末行另起一段：关键词：3–5 个，分号隔开，至少含一个方法名与一个研究对象名。

禁用反例（这类句子出现即整段重写，不做修补，不做润色）：
"本文分析了……的影响，并提出了……的方法，最后对……进行了讨论，
 所得结论为……提供了参考。"
判据很硬，照着判：一句话里既没有 C##/A##/N## 编号，也没有带单位的数字，
它就是空转句，删掉或换成有编号有数字的写法。此类句子全文超过一句即本卡未完成。

字数与版式：摘要单独成页、不超过 1 页 A4。细则以
数模作战包/dryrun/format-rules.md（V3-5 判据抽取件）为准；若该文件尚未生成，
按"中文摘要 500 字左右 + 关键词"执行，明早开赛后第一时间用研究生赛区官方模板复核。

输入材料：
SPEC.md：{SPEC.md 全文}
assumptions.md：{assumptions.md 全文}
numbers.md：{numbers.md 全文}
各问方法与假设：{每问方法与关键假设一句话}
各问代表结果：{每问代表结果的 N##}
```
- **必落文件**：`{工作区}/paper/sections/00-摘要.md`（三段 + 关键词行；这里的数值同样必须是 `值 [N##]` 形态，因为该文件在 `paper/sections/` 下，会被 `check_numbers.py` 扫描）。
- **30 秒人工判定**：全文搜四个词——"本文分析了""并提出了""进行了讨论""提供了参考"，命中任一即退回重写；数一下第 3 段的数字是不是全部挂着 `[N##]`；第 2 段每一问是否有 A##。
- **已知失效模式**：① 摘要要不到具体数字——这不是写作问题，是结果没真出来，回退卡 3-2 补自证包，禁止用定性句填空 ② 关键假设只在正文出现、摘要里没有 A##（评委第一眼看的就是摘要里的假设是否可疑）③ 摘要里的值和台账不一致 → V3-1 判"同源不同值" ④ 加写第四段"创新点与不足"，段落数即判据，多一段就是没按契约写 ⑤ 在 Word 里直接改摘要而没同步回 md，机器扫描通过而纸质稿错。
- **验证状态**：未压测

### 卡 4-3  数字回填
- **触发时机**：P2.3 起，每有一问的 `verify.py` 转绿就跑一次该问相关节；R3（提交前 ≥3h）全队统一跑一次全文。提交前 90 分钟之后不再执行本卡（改一个数要重跑整条链，90 分钟来不及）。
- **输入**：`{numbers.md 全文}`、`{待回填节：paper/sections/NN-*.md 全文}`、`{SPEC.md 的单位列}`、`{工作区}`
- **prompt**：
```text
你是数字台账的执行者。唯一规则：论文里只引用编号，不允许把数值抄第二遍。

台账 numbers.md：{numbers.md 全文}
待处置正文：{待回填节全文}
SPEC.md 单位约定：{SPEC.md 的单位列}

1. 凡来自计算结果的阿拉伯数字，替换成 `值 [N##]（单位）`。N## 由你在台账里按
   "值 + 单位 + 来源脚本"三项同时对上号才允许挂；只对上两项以内不算对上。
2. 同一个 N## 在全部正文里只允许出现一次。check_numbers.py 把同一 ID 的第二次
   出现判为"同源重复"直接 FAIL。第二处需要提到时改成文字指代：
   "见 4.2 节表 3 对应行"，不再重复写值。
3. 台账里没有的数字：停下来提问，禁止自己造数，禁止四舍五入凑一个近似值。
   单列【缺台账数字清单】，每条五行：
   数字 | 出现在哪节哪句 | 它本该由哪个脚本产生 | 那个脚本是否真跑过（跑过给命令）
   | 建议的登记命令（照抄格式：
   $PY scaffold/scripts/numbers_add.py {工作区} <值> <单位> <来源脚本> <出现位置> <复算方式>）
   在该清单被人工处置完之前，原句改成定性表述，不留裸数字。
4. 结构性序号保留原样、不算数值：图号、表号、式号、章节号、"第 4 问"
   （脚本对这类前缀已做排除）。但"五折交叉验证""三个阶段"这类计数请写中文数字，
   不要写 `5 折`——它会被当成未挂台账的数值。
5. 单位与 SPEC.md 的单位列逐字一致。需要换算时只能引用 tools/units.py 里的常量名，
   禁止在正文手写 1024、60、3.14 这类换算系数，也禁止"约等于"。
6. 区间与阈值：结果值取实测值，不许取区间中点。若只有区间，进【缺台账数字清单】
   并要求补测。
输出：改写后的本节全文（保持原小节标题与行序），行内不加解释性注记；
末尾附一行统计 `本节数值 X 处，已挂 N## 共 Y 处，缺台账 Z 处`。
```
- **必落文件**：改写后覆盖 `{工作区}/paper/sections/NN-*.md`；`【缺台账数字清单】`进 `{工作区}/log/数字回填.md`（每节一节，标题带节号，不留空标题）；缺的数字经人工确认后由 `数模作战包/scaffold/scripts/numbers_add.py` 追加——**禁止手改 `numbers.md`**（任何班可追加、不可改值）。
- **30 秒人工判定**：跑 `$PY scaffold/scripts/check_numbers.py {工作区} 0.95`，退出码 0 才算完；再看【缺台账数字清单】——非空就立刻转卡 5-3 分派，不许在正文里留裸数字继续往下写。
- **已知失效模式**：① 手抄数值 → V3-1 判"同源不同值"，而这正是 AI 最容易自我说服的一类错（它记得一个"差不多"的数）② 把粗估区间的中点当结果值 ③ 同一 N## 在正文出现两次 → dup 判 FAIL，改稿时最容易踩 ④ 在 Word 里回填：机器只扫 `paper/sections/*.md`，Word 里改得再漂亮也不算通过，回填必须发生在 Markdown 阶段 ⑤ 把"改进路径里希望有的数字"当成结果写进正文 ⑥ 用 `[N03]` 之外的自造写法（`(N03)`、`N03号`），正则不认，链接率白掉。
